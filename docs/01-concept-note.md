## 0. 一句話定義

**輸入一個號碼或一個公司名，產出「讀得懂、複製得到、看得到圖、下載得到原文件」的專利內容。**

---

## 1. 不可再化約的痛 (irreducible pain)

> 要讀懂一件專利，資訊被切在三個平台上：**能複製的文字**在 Google Patents、**能看的圖與原文件**在 Espacenet、**PATENTSCOPE 連 `US20250383260A1` 這種號碼都不吃**。每讀一件，就要手動開三個分頁拼一次。

**v2 延伸**：同樣的散落也發生在「這家公司在做什麼」——申請人檢索與單件閱讀分屬不同介面，找到一批案子之後，還是得一件一件重新拼。

這個痛可以完全不提任何技術名詞就講清楚，通過第一性原理檢驗——它是真需求，不是找問題來套方案。

## 2. 為什麼必須存在

**不做會怎樣**：每讀一件專利的固定成本 ≈ 開三個分頁 + 號碼格式試錯 + 手動拼湊。研究導向的閱讀是高頻行為（確認一個研究方向通常要讀 10–50 件），這個固定成本會**直接壓縮實際讀得完的件數**——痛的不是單次麻煩，是它讓人少讀。

**第一個真實使用者**：使用者本人。環境：Windows 11、本機單機自用、非商業用途（研究方向確認與學習）。

## 3. 本質核心 vs 附屬 (essential core vs accident)

**本質核心（第一版唯一要做滿的事）—— 兩條入口，同一張卡**
> 1. 一個號碼進來 → 一張完整的單件專利卡出去。
> 2. 一個申請人／公司名進來 → 一份結果列表 → 點進去就是同一張卡。

第 2 條刻意設計成「回到第 1 條」，避免長出第二套呈現邏輯。

**標示為擴充，不是範圍（labeled extensions, NOT scope）**

| 擴充 | 使用者立場 | 何時談 |
|---|---|---|
| 技術地圖 / landscape | 「未來很有野心但也很有用」 | 核心穩定後 |
| 記憶 / 個人知識庫 | 與技術地圖綁在一起提出 | 同上；**但資料模型今天就要為它留路** |
| TW / CN / JP / KR 管轄 | v2 由使用者收斂移出 | 第一版穩定後逐局評估 |
| 翻譯（→ 繁體中文） | v1 裁定為 extension；**v2 因範圍收為 EP/US 而暫時無意義** | 加入非英語管轄時才重啟 |
| USPTO 審查歷程 (file wrapper) | v2 移出（見 §7.3） | 若日後需要 prosecution 資訊 |
| 全文／概念檢索（非結構化） | 未提出 | 明確不在第一版 |
| 兩件並排比對 | 我提出、使用者未裁定 | 待定 |

## 4. 邊界 —— 本工具明確不做的事 (boundaries)

1. **只做結構化欄位檢索，不做全文概念檢索。**（v2 改寫）可以用申請人、發明人、標題／摘要關鍵字、分類查；**不做**「描述一段技術概念幫我找相似案」那種語意檢索。
2. **第一版只做 EP 與 US 兩個管轄。**（v2 新增）TW / CN / JP / KR 明確延後。
3. **不內建翻譯引擎。** v2 因範圍收為全英文管轄，連插槽都不預留——加入非英語管轄時才重啟此議題。
4. **不做 FTO / 侵權判斷 / 法律意見。** 法律狀態只如實呈現，不解讀。
5. **不採購付費資料源。** 排除 PATENTSCOPE 官方 API（CHF 2,000/年）與 Lens.org（2026-06 起個人商用需付費授權）。
6. **不接 USPTO ODP。**（v2 新增，見 §7.3）
7. **不做多使用者、不做雲端部署。** 本機單人自用。**這條在接上 EPO OPS 後從偏好升級為契約義務**：OPS 條款 3.2 禁止把資料「本身」提供給公眾，違反者依 8.3 屬重大違約、EPO 可不經預告終止。加值後的產品可散布，原始資料本身不可。詳見 `docs/03-ops-terms-compliance.md`。
8. **不以無頭瀏覽器 (headless browser) 為主路徑。** 只作為備援轉接器，且必須有具名理由才啟用。
9. **不採用 PatZilla 作為地基。**（理由見 §7.4）

> 標準指令：**不要為了擴充而擴充。** 核心一旦滿足即建議收手。

## 5. 角色 (actors)

| 角色 | 說明 |
|---|---|
| **研究者（主要）** | 使用者本人。目的是確認研究方向、學習技術內容。不是專利師、不做商業決策。 |
| **過去的自己（次要，未來）** | 「記憶」擴充的真正讀者——三個月後想找回當初讀過的東西。這個角色決定了資料要留存，不能查完即丟。 |

## 6. 業務規則 (business rules)

| ID | 規則 | 為什麼 |
|---|---|---|
| **BR-1** | **輸入寬容。**（v2 擴充）系統須自行判斷輸入類型並分派：<br>・**號碼**：`US20250383260A1` / `US 2025/0383260 A1` / `US2025383260A1` / `11,123,456` / 申請號<br>・**申請人／公司名**：如 `Corning`、`台積電`（英文名）<br>・**發明人姓名**<br>使用者不需要先選「我要查哪一種」。 | 這是使用者被 PATENTSCOPE 卡住的原點；EPO OPS 的 number-service 與 CQL 檢索現成可用。 |
| **BR-2** | **來源優先序依欄位而變**，不是固定一套。 | 見 §7.3。 |
| **BR-3** | **欄位缺漏必須自曝。** 拿不到就顯示「此源無此資料」，**不得靜默留白**。 | 靜默留白會讓使用者誤以為「這件專利沒有這項」，而不是「工具沒拿到」。研究用途下這是實質錯誤。 |
| **BR-4** | **每個欄位標註來源。** | 整合工具的信任基礎：使用者要知道這段摘要是誰給的。 |
| **BR-5** | **查過即入庫。** 本地資料庫是「個人專利庫」，不是「查詢快取」。 | 為「記憶／技術地圖」擴充預留；兩種心態的 schema 差很多，事後搬家比現在決定貴。 |
| **BR-6** | **配額自我節制。** EPO OPS 免費層公平使用上限為 **4 GB/週**，須主動計量並在接近上限時降級而非硬撞。 | 撞上限會整週停擺。檢索（尤其大公司）會顯著加快消耗。 |
| **BR-7** | **只以單件頁形式接觸 Google Patents，永不自動化其搜尋。** | `robots.txt` 為 `Disallow: /*` 但 `Allow: /patent/`——單件頁被允許，搜尋不被允許。**這也是為何申請人檢索只能走 OPS。** |
| **BR-8** | **申請人名稱變體必須攤開，不得假裝一個名字＝一家公司。**（v2 新增）查詢結果須列出實際命中的申請人名稱字串，供使用者勾選收斂；並明示「本結果可能不完整」。 | 專利庫中同一公司有大量寫法（`Samsung Electronics Co., Ltd.` / `SAMSUNG ELECTRONICS CO LTD` / 子公司 / 併購後改名）。查一個名字**必定漏**。這是資料的性質，不是工具缺陷——但把它藏起來就變成工具缺陷。與 BR-3 同源。 |

## 7. Phase 1 勘查結果 (prior art & source sweep)

### 7.1 假設對照表 —— 哪些原有信念被推翻

| 原本相信 | 查證後 | 影響 |
|---|---|---|
| 需要無頭瀏覽器模擬實機輸入 | **錯。** 兩個主源有官方 API／被 robots.txt 允許 | 主路徑改為 API；瀏覽器降為備援 |
| Espacenet 沒有摘要、文字不好複製 | **是網頁 UI 的限制，不是資料的限制。** OPS API 有 abstract / claims / description | 使用者最大的兩個痛點由同一個 API 解決 |
| Google Patents 難拿圖與原文件 | **部分錯。** 實測 `US20250383260A1`，圖檔 URL 可直接定址（15 張）| Google Patents 升格為 US 文字與圖片的主源 |
| 非英語案要自己處理翻譯 | **錯**（Google Patents 對 CN/JP/KR 本來就給英文機翻）；**且 v2 範圍收斂後此題暫時消失** | 翻譯完全移出第一版 |
| PATENTSCOPE 可以接 | **不可行。** SOAP、CHF 2,000/年、每 IP 每分鐘 <10 次擷取 | 降為深連結 |
| 需要 USPTO ODP 才能處理 US 案 | **錯。**（v2）US 的書目/同族/法狀/圖式由 OPS 供應，全文由 Google Patents 供應（已實測）| USPTO ODP 移出第一版 |

### 7.5 差異化陳述（誠實版）

本工具**不會**在檢索與分析能力上勝過 PatSnap / Orbit，也不該嘗試。它唯一的勝場是：

> **現有免費工具沒有任何一個把「可複製的全文 ＋ 高品質圖式 ＋ 原文件 PDF ＋ 同族與分類」放在同一屏。** 使用者現在得開三個分頁手動拼。

v2 加入申請人檢索後，這句話仍然成立——檢索只是**通往那一屏的第二條入口**，不是新的競爭主張。

### 7.6 環境限制（已確認）

- Windows 11 本機、單人使用、非商業。
- 專案目錄 `D:\AIWork\PatentsGrabber`，尚未初始化為 git repo。
- 無雲端部署需求；啟動方式應為單一指令／單一捷徑。

## 9. 前提與可翻盤條件 (premises & refutability)

**前提**

| 類型 | 內容 | 來源 | 狀態 |
|---|---|---|---|
| P-env | Windows 11、本機單人、專案目錄尚未初始化為 git repo | 模型（已驗證）| 已驗證 |
| P-intent | 用途為研究方向確認與學習，非商業、非 FTO | **使用者** | 已裁定 |
| P-intent | **第一版管轄收斂為 EP / US** | **使用者**（v2）| 已裁定 |
| P-intent | 翻譯不列入本體 | **使用者** | 已裁定（v2 因範圍收斂而暫時無實作意義）|
| P-intent | **申請人／公司名檢索納入第一版** | **使用者**（v2）| 已裁定 |
| P-intent | 避免 USPTO ODP 的申請複雜度 | **使用者**（v2）| 已裁定，且經評估對核心無損 |
| P-validity | 各資料源的 API 現況、配額、CQL 欄位碼 | 模型（2026-08-20 網路查證）| 已驗證，**屬易變事實** |
| P-validity | Google Patents 單件頁可穩定供應 US 全文 | 模型（**一件實測**）| 一手證據，但**樣本數 1** → S-2 擴大驗證 |

**成立條件 (holds when)**：EPO OPS 免費層與 Google Patents 的 `Allow: /patent/` 維持在 2026-08-20 查得的狀態。

**會被推翻的情況 (overturned by)**：
- Google Patents 調整 `robots.txt` 或改為需登入 → **Stage 0 整個失效**，須全面回退至 OPS，此時 S-3（OPS 的 US 全文覆蓋）從附帶觀察升級為阻斷性風險。
- S-6 顯示 OPS 檢索結果上限過低（如僅數百筆）→ 申請人檢索的實用性下降，§3 的第 2 條入口需重新定位為「窄查詢」而非「看這家公司在做什麼」。
- EPO 變更免費層條件 → 重新評估 BR-6 與整體可行性。
- 使用者要求加回 TW/CN/JP/KR → §4 邊界 2、3 失效，翻譯議題重啟，v1 的 S-1 風險回歸。

**證據層級**：資料源能力為官方文件與第三方客戶端文件（二手）＋ 一件實測（一手，n=1）；US 全文覆蓋率為推論。

**review-when**：任一資料源公告變更免費層或 robots.txt 時；或 Stage 0 完成時（屆時 §7.2、§9 需以實測樣本更新）。

## 11. 變更記錄 (change log)

### v1 → v2（2026-08-20，來源：使用者三點指示）

| 項目 | v1 | v2 | 理由 |
|---|---|---|---|
| **邊界 1** | 「不做檢索引擎，第一版只做已知號碼 → 讀懂」| 改為「只做結構化欄位檢索，不做全文概念檢索」| 使用者要求納入公司名／申請人查詢。**這是推翻，不是補充**——已明確記錄以免後續 session 誤以為 v1 邊界仍有效 |
| **管轄範圍** | US / EP / TW / CN / JP / KR | **僅 EP / US** | 使用者提議收斂。消除翻譯需求與非英語全文覆蓋風險 |
| **翻譯** | 列為 extension，預留 `TranslationProvider` 插槽 | **連插槽都不留** | 範圍全為英文管轄，留介面等於無名的未來，違反「一個介面一個實作」原則 |
| **USPTO ODP** | 核心必要（美國原文件與審查歷程）| **移出第一版** | 使用者指出申請複雜度高。評估後確認其獨門價值（file wrapper）不屬「讀懂技術」核心 |
| **TIPO** | 視需要接入 | 移出 | 隨管轄收斂 |
| **BR-1** | 號碼寬容輸入 | 擴充為「輸入寬容」，含申請人／發明人 | 隨檢索納入 |
| **BR-8** | 無 | **新增**：申請人名稱變體必須攤開 | 專利資料的固有性質，不揭露即成缺陷 |
| **S-1** | 最高風險項（非英語全文覆蓋）| **註銷** | 隨管轄收斂消失 |
| **S-6 / S-7** | 無 | 新增（檢索結果上限、名稱變體離散度）| 隨檢索納入 |
| **分階段** | 無 | **新增 §8.2** | 使用者仍在等 OPS 金鑰；切出零金鑰即可開工的 Stage 0 |

**淨效果**：第一版**比 v1 更輕**。移除的（四個管轄的語言與覆蓋處理、一組金鑰、翻譯插槽）明顯重於新增的（一個 CQL 查詢 ＋ 一個結果列表視圖）。
