**這份回顧的成立條件**：它描述的是 `0cc20b1` 這一份程式碼。任何一次改動 gate 或
擷取器都會使 §1–§2 的表格部分失效——**推翻方式**：重跑一次同樣的比對，成本約 20 分鐘。

**一個要先更正的印象**：上一輪對話裡我說「`R-*` 在 gate 與原始碼中一次都沒出現」——

## 3. 儀器體檢：守門員本身可信嗎

### 3.1 做得對的地方（要保留，不要在重構時弄掉）

| 儀器紀律 | 在哪 |
|---|---|
| **壞輸入必須被擋下**（負向校準） | `check_reading.py`：拆掉段落標記的頁面必須失敗，且會明說「checker 沒在量任何東西」 |
| **指標對它要抓的缺陷校準過** | claim coverage 對舊解析器重播 → 0.282 擋下、1.000 放行；巢狀樣本在新舊兩版都 1.000（不會亂叫） |
| **查詢建構的校準** | `check_search.py` §1：手工兩子句查詢必須被 matcher 拒絕，證明這個檢查有能力失敗 |
| **系統性故障偵測** | `check_reading.py`：某個指標在**所有**文件上都是 0 → 印 `SYSTEMATIC FAILURE`，把「全體一致」視為儀器故障而非結論 |
| **正反雙向對照** | figref 三正三負；EN/DE/FR 附屬項九案雙向；零結果是答案不是錯誤 |
| **紅燈轉為斷言而非刪除** | `verify_ops.py` §4：US 全文不可用從「失敗」改寫成「預期不可用」，OPS 哪天開放反而會 FAIL——這是**設計成警報的紅燈** |

這一組是 Stage 1 真正的資產。下面的缺口都比不上它們重要。

### 3.2 盲點（按影響排序）

**I-1 · `check_reading.py` 是回歸測試，不是活的偵測器。**
它讀的是 `var/raw/` 裡 20 份 **存檔 HTML**。若 Google Patents 明天改掉描述標記，
這支檢查 **仍然 20/20 全綠**，因為它比對的是舊檔案。`docs/05` §7 寫著
「The checker is the tripwire」——這句話**只在有人重新抓頁面時成立**。
今天沒有任何東西會重抓。這是本次回顧最重要的一條：**專案最活躍的外部依賴，
偵測器是靜態的。**
**已處理（2026-08-27）**：`tools/check_freshness.py` 從另一側補上——重抓三份取樣頁，
比對解析出來的結構數量。存檔仍然是基準線，探針不覆寫它。

**I-2 · schema 常數的規則只是一句叮嚀，沒有機制。**
`CLAUDE.md` 要求「改擷取器就在同一次 commit 動 `READING_SCHEMA` / `OPS_CARD_SCHEMA`」，
而這條規則是**踩過兩次**才寫下的。再讀（`service.py:555`、`:529`）時的重新推導機制是好的、
自動的；問題只在「忘記加一」——而防止忘記的目前手段是記憶。
這正是全域規則說的反例：規則應寫成**資產的性質**，不是對路徑的叮嚀。
**已處理（2026-08-27）**：`tests/test_extractor_fingerprint.py` 把擷取器的 AST（去掉
docstring）雜湊後釘在常數旁邊。實測過會叫：對 `_fig_number` 插入一行後即 FAIL，
還原後即 PASS。註解與排版不會誤觸。

**I-3 · 配額只被印出來，沒有被斷言。**
BR-6 的兩個實質承諾——「頁面位元組隨看隨取」「重讀不花配額」——都沒有檢查。
`Usage.summary()` 是給人看的字串。若某次重構讓建卡順手預抓縮圖，
所有 gate 仍然全綠，只有 EPO 的週計數器會安靜地爬。

**I-4 · 沒有一鍵執行，也沒有 CI。**
五支 gate 各自獨立執行，其中三支要網路與配額。實務上「守門」等於「我記得要跑」。
本機單人、無 remote，CI 不適用；但一支聚合器（先跑離線的，再問要不要跑耗配額的）
是成立的。
**已處理（2026-08-27）**：`tools/run_gates.py`，分三層 local／net／ops，
預設只跑不出網的四支；沒跑到的會被列成「not run」而不是消失。

**I-5 · 分數不可跨時間比較。**
`check_reading` 的「20/20」分母是 `var/raw/` 的檔案數，會隨取樣增加而變；
`check_search` 的「20/20」是檢查項數。兩個 20 意義不同，紀錄裡並排時看起來像同一種東西。
**已處理（2026-08-27）**：聚合器的 summary 每一列都印出該分數的單位
（per DOCUMENT／per CHECK／per METRIC）。

**I-6 · 兩支 gate 沒有校準案。**
`smoke_service.py` 與 `tests/test_ops_number_formats.py` 全綠，但沒有任何
「已知為真應被擋下」的反例證明它們有能力失敗。相較 §3.1 的紀律，這兩支是漏網的。

## 4. 建議與落地結果（四條全數完成，2026-08-27）

> 前提：Stage 1 的核心需求已滿足，這四條沒有一條是「功能不足」。
> 它們買的是「壞掉時會被發現」。四支新東西**都不改任何既有行為**。

**建議 1 · 新鮮度探針（對應 I-1）── 已完成：`tools/check_freshness.py`**
重抓 `US6285999B1`（2001 年公告、限定事項為兄弟節點）、`US20250383260A1`
（2025 年公開、`ul.description` 版式）、`EP1000000A1`（EP 版式）三件——刻意一件一種
咬過人的標記版式——與存檔版比對 blocks／paras／claims／claim_parts／figrefs／chars，
容差 10 %，逐字內容不比。抓下來的頁面 **不寫回 `var/raw/`**，基準線因此不會被探針
自己汙染。首跑結果：三件全部**逐項完全相同**。校準：把活頁面的段落標記拿掉後
必須被抓到，實得 `blocks: 65 -> 7 (-89%)`。失敗語意分三級——0 通過、1 有偏移、
**2 無法判定**（抓不到就說抓不到，不冒充通過）。

**建議 2 · 擷取器指紋（對應 I-2）── 已完成：`tests/test_extractor_fingerprint.py`**
14 個閱讀擷取函式 ＋ 4 個 OPS 建卡函式，取 AST（去 docstring）雜湊釘在
`READING_SCHEMA` / `OPS_CARD_SCHEMA` 旁邊。用 AST 而不是原始碼字串，是為了讓註解與
排版改動不會誤觸——會誤觸的守門員很快就會被習慣性忽略。**實測過它會叫**：對
`_fig_number` 插入一行 → FAIL 並印出該用的新雜湊；`git checkout` 還原 → PASS。
另有一個單元校準（改註解不變、改回傳值必變）。基準線取自 `main@cacfde9`，
沒有為了建立基準而動任何常數。

**建議 3 · 版面自檢（對應 R-9／R-10）── 已完成：`tools/check_layout.py`**
以 DevTools 協定（`websockets` 已在環境內，不必裝 Playwright）驅動無頭 Chrome，
量的是**頁面自己的函式**（`measurePx()`、`READ`），不是把規則抄一份去測自己的抄本。
13 項全過，且複現了 §5.2 的紀錄數字：

| 檢查 | 結果 |
|---|---|
| R-9 無死區 | 1920：面板 726 px／欄 612 px，差 114 px；2560：面板 801 px／欄 684 px，差 117 px（上限 220） |
| R-9 無水平溢位 | 1920、2560 皆 `scrollWidth == clientWidth` |
| R-10 自動配對 | 1920 → 17px/72ch；2560 → 18px/76ch，都在 16–18px／68–76ch 範圍內 |
| R-10 反向 | 釘住 60ch 後跨兩個尺寸不變，且頁面自陳處於讀者模式 |
| 校準（兩個） | 面板改成 90 % → 報出 1620 px 死區（正是 R-9 要防的缺陷）；塞入 4000 px 元素 → 報出水平溢位 |

刻意不做的：像素級外觀、顏色、深色模式——那仍然是人眼的事，工具自己在結尾這樣寫。

**建議 4 · 一鍵聚合器（對應 I-4／I-5）── 已完成：`tools/run_gates.py`**
分三層：`local`（四支，完全不出網）、`--net`（加兩支抓 Google Patents 單件頁）、
`--all`（加兩支耗 OPS 配額，且執行前明白說出成本）。Summary 每列標明該分數的單位，
沒跑到的列成 `not run (net)` 並附一句「沒跑到的 gate 不等於通過的 gate」。
**全套 8 支實跑結果：全過**（見 §4.1）。

**維持不做**（理由不變）：BR-7 的 URL pin、R-7 的自動檢查、F-9/F-10 的上限監看、
I-6 的補校準。另外新增一條不做：`check_freshness` 的取樣**不擴到全部 20 件**——
每跑一次就是 20 次外部請求，而三件已足以偵測版式變更；真的要全面重掃時，
`tools/probe_coverage.py --refresh` 本來就在那裡。

## 6. 命令列介面（`pgb`）加入後的覆蓋變化 — 2026-09-11

Stage 1 的每一條規則原本都只在**瀏覽器那一面**被守。命令列讓同一批規則多了一個
入口，而入口不同，會壞的地方也不同：瀏覽器的讀者是人，會看到空白就發問；命令列的
讀者是程式，看到空欄位就當成事實往下走。所以 `tools/check_cli.py` 守的不是新規則，
是**舊規則在新入口上的同一批性質**。

| 性質 | 為什麼在這個入口上是新的 | 對照（正／負） |
|---|---|---|
| `--json` 時 stdout 只有一個 JSON 物件 | 解析端會把進度訊息誤讀成結果，而且會**成功**地誤讀 | 正：不帶 `--json` 時 stdout **不是** JSON；人看的字串出現在 stderr、不得出現在 stdout |
| 預設不輸出全文 | 使用者裁定（2026-09-11）：agent 讀到的東西會離開本機 | 正：`--full` 必須含有全部三個文字欄位與植入的標記字串。**只驗精簡模式會在一張本來就沒有全文的卡片上滿分** |
| 任何指令都不得印出金鑰 | 命令列的輸出會整段進入 agent 的 context | 正：偵測器對「確實含有假金鑰的字串」必須叫；且假金鑰確實寫進了設定檔 |
| 花配額是選擇性的 | 迴圈呼叫的成本由呼叫端承擔，人點擊的成本由人自己承擔 | 正：要求一頁不在磁碟上的圖必須**非零離開**，不得回一個空的 files 清單 |
| 兩個行程可同時持有專利庫 | 只有這個入口會和程式視窗同時開著 | 正：持有 EXCLUSIVE 鎖時必須以 `busy`（exit 6）具名回報，不得靜默卡住 |

**這一關的尺（照全域守門規則，與分數並列）**：「四個並行寫入者全部成功」是**下限，
不是證明**——在這個資料量下，舊的 rollback journal 多半也會通過。確定性的斷言是
`journal_mode` 本身；並行那一項的價值來自它的對照（鎖住之後它必須失敗），沒有對照
的那一半只是沒出事。

### 6.1 這一關第一版是綠的，而它漏掉了兩個 blocker

值得寫下來的不是缺陷本身，是**綠燈的來源**。`check_cli.py` 第一版對 `lookup`
的精簡模式做了完整的正反對照，然後回報 ALL PASS——而同一支程式的 `search`
每一列都夾帶一整段 OPS 摘要送出去。守門員沒有錯判，它**根本沒跑那個指令**。

| 誰找到 | 缺陷 | 為什麼儀器沒叫 | 已修 |
|---|---|---|---|
| code-reviewer | `search` 預設輸出每列的摘要全文，且沒有 `--full` 可以「選擇加入」 | 關卡的指令矩陣只有 `doctor`／`lookup`／`figures`，沒有 `search`／`pdf` | 抽出 `lean_search()`，離線雙向對照＋結構檢查；指令矩陣補齊 |
| security-engineer | `parse_pages` 先把區間展開成 list 才檢查上限，`--pages 1-99999999999` 會先吃光記憶體 | 上限檢查存在，但**順序**錯了，而斷言只看「超過上限會被拒」，不看它**何時**被拒 | 上限改在**數字**上檢查；新增計時對照（必須瞬間拒絕） |
| 實測 agent | 全部頁面都失敗時，回傳沒有 `cost`／`quota`，呼叫端不知道自己被計費了 | 斷言只檢查「失敗要非零離開」，沒檢查失敗信封的**欄位集合** | `failure()` 一律帶 `cost`／`quota`；斷言改成比對成功／失敗兩者的 key 集合 |
| 實測 agent | `--pages 11` 是「前 11 頁」而非「第 11 頁」，一次誤解花掉 11 倍請求 | 這不是缺陷，是語意選擇——但選了**貴的那一邊** | 使用者裁定：裸數字＝該頁 |
| 實測 agent | EPO 清單說有 14 頁但第 11–13 頁 404，且每次重問都重新計費 | 沒有任何檢查涵蓋「同一個否定答案被買兩次」 | 404 記進 `absent-pages.json`；重問 0 請求，`--refresh` 可忘掉 |
| code-reviewer | `cost.network` 在全部命中快取時仍報 `epo_ops` | 斷言看 `ops_requests`，沒看 `network`，兩者互相矛盾也不會叫 | `network` 由實際結果推導；新增斷言 |
| code-reviewer | `pdf --pages 0` 會產生一個零頁 PDF | 只檢查上限，沒檢查下限 | 兩端都驗；`figures` 的對照補到 `pdf` |
| 自查 | `TEXT_KEYS` 是黑名單：日後新增帶文字的欄位會靜默外洩 | 黑名單的漏洞在**未來**，任何當下的斷言都測不到 | 加一條不需要名單的規則：payload 內任何超過 400 字元的字串一律換成長度，並具名記錄 |

**這一輪的方法本身值得留**：三個獨立審查者（對抗式 code review、防禦式資安審查、
一個只拿到 SKILL.md、沒看過原始碼的執行者）之中，**只有執行者**能找到「語意選錯邊」
與「失敗信封少欄位」這兩條——因為那兩條要真的花掉一次配額才會痛。靜態審查找結構，
實跑找代價。

**仍然沒有守到的**（照 §3 的誠實標準寫下來，不寫成已完成）：

- 命令列與**真實** OPS 的互動（憑證有效時的取圖、配額表頭）——`check_cli.py` 全程
  離線，那一半仍由 `verify_ops.py` 與人工驗收覆蓋。`search` 的精簡是在**函式**上
  對照的，不是在真實檢索上；2026-09-11 以一次真實檢索人工確認（5 列、0 個
  `abstract` 欄位、`abstract_chars` 為 244–990，即原本會外流約 3,600 字元），
  但那是一次性證據。
- **跨行程的配額總量**。`MAX_PAGES` 只管一次呼叫；連續呼叫 `pgb` 二十次沒有任何
  程式面的攔截，SKILL.md 的「不要對號碼清單跑迴圈」是**請求，不是控制**。
  資安審查明確指出這一點，這裡照實記下而不假裝已解決。
- **設定檔本身**。命令列的任何輸出都不含金鑰（有斷言），但金鑰以明文躺在
  `.env`／`settings.env`，而呼叫者是一個有檔案讀取工具的 agent。這條界線不在本
  專案手上，屬於呼叫端的權限設定；SKILL.md 已改成明講它守不住，而不是暗示它守得住。
- 圖檔內容是否真的是該案該頁——這是圖像判讀，工具只能證明檔案存在且路徑可讀。
  2026-09-11 以人（模型）實讀 `p0003.png` 確認：頁首為
  `Patent Application Publication / Dec. 18, 2025 / Sheet 3 of 14 / US 2025/0383260 A1`，
  圖面為 FIG. 3。這是**一次性**證據，不是可重跑的斷言。
