## 0. 一句話定義

**輸入任意格式的專利號碼，產出一張「讀得懂、複製得到、看得到圖、下載得到原文件」的單件專利卡。**

---

## 1. 不可再化約的痛 (irreducible pain)

> 要讀懂一件專利，資訊被切在三個平台上：**能複製的文字**在 Google Patents、**能看的圖與原文件**在 Espacenet、**PATENTSCOPE 連 `US20250383260A1` 這種號碼都不吃**。每讀一件，就要手動開三個分頁拼一次。

這個痛可以完全不提任何技術名詞就講清楚，通過第一性原理檢驗——它是真需求，不是找問題來套方案。

## 2. 為什麼必須存在

**不做會怎樣**：每讀一件專利的固定成本 ≈ 開三個分頁 + 號碼格式試錯 + 手動拼湊。研究導向的閱讀是高頻行為（確認一個研究方向通常要讀 10–50 件），這個固定成本會**直接壓縮實際讀得完的件數**——痛的不是單次麻煩，是它讓人少讀。

**第一個真實使用者**：使用者本人。環境：Windows 11、本機單機自用、非商業用途（研究方向確認與學習）。

## 3. 本質核心 vs 附屬 (essential core vs accident)

**本質核心（第一版唯一要做滿的事）**
> 一個號碼進來 → 一張完整的單件專利卡出去。

**標示為擴充，不是範圍（labeled extensions, NOT scope）**

| 擴充 | 使用者立場 | 何時談 |
|---|---|---|
| 技術地圖 / landscape | 「未來很有野心但也很有用」 | 核心穩定後 |
| 記憶 / 個人知識庫 | 與技術地圖綁在一起提出 | 同上；**但資料模型今天就要為它留路** |
| 翻譯（→ 繁體中文） | **明確裁定：不當本體，做 extension** | 留插槽、零實作 |
| 關鍵字/概念檢索 | 未提出 | 明確不在第一版 |
| 兩件並排比對 | 我提出、使用者未裁定 | 待定 |

## 4. 邊界 —— 本工具明確不做的事 (boundaries)

1. **不做檢索引擎。** 不與 PatSnap / Orbit / Espacenet 的搜尋能力競爭。第一版只處理「**已知號碼 → 讀懂**」。
2. **不內建翻譯引擎。**（使用者裁定）
3. **不做 FTO / 侵權判斷 / 法律意見。** 法律狀態只如實呈現，不解讀。
4. **不採購付費資料源。** 排除 PATENTSCOPE 官方 API（CHF 2,000/年）與 Lens.org（2026-06 起個人商用需付費授權）。
5. **不做多使用者、不做雲端部署。** 本機單人自用。
6. **不以無頭瀏覽器 (headless browser) 為主路徑。** 只作為備援轉接器 (fallback adapter)，且必須有具名理由才啟用。
7. **不採用 PatZilla 作為地基。**（理由見 §7）

> 標準指令：**不要為了擴充而擴充。** 核心一旦滿足即建議收手。

## 5. 角色 (actors)

| 角色 | 說明 |
|---|---|
| **研究者（主要）** | 使用者本人。目的是確認研究方向、學習技術內容。不是專利師、不做商業決策。 |
| **過去的自己（次要，未來）** | 「記憶」擴充的真正讀者——三個月後想找回當初讀過的東西。這個角色決定了資料要留存，不能查完即丟。 |

## 6. 業務規則 (business rules)

| ID | 規則 | 為什麼 |
|---|---|---|
| **BR-1** | **號碼寬容輸入。** `US20250383260A1` / `US 2025/0383260 A1` / `US2025383260A1` / `11,123,456` / 申請號皆須可查。 | 這是使用者被 PATENTSCOPE 卡住的原點；EPO OPS 的 number-service 現成可用。 |
| **BR-2** | **來源優先序依語言與國別而變**，不是固定一套。 | 見 §7 的來源分工結論。 |
| **BR-3** | **欄位缺漏必須自曝。** 拿不到就顯示「此源無此資料」，**不得靜默留白**。 | 靜默留白會讓使用者誤以為「這件專利沒有這項」，而不是「工具沒拿到」。這是研究用途下的實質錯誤。 |
| **BR-4** | **每個欄位標註來源。** | 整合工具的信任基礎：使用者要知道這段摘要是誰給的。 |
| **BR-5** | **查過即入庫。** 本地資料庫是「個人專利庫」，不是「查詢快取」。 | 為「記憶／技術地圖」擴充預留；兩種心態的 schema 差很多，事後搬家比現在決定貴。 |
| **BR-6** | **配額自我節制。** EPO OPS 免費層公平使用上限為 **4 GB/週**，須主動計量並在接近上限時降級而非硬撞。 | 撞上限會整週停擺。 |
| **BR-7** | **只以單件頁形式接觸 Google Patents，永不自動化其搜尋。** | `patents.google.com/robots.txt` 為 `Disallow: /*` 但 `Allow: /patent/`——單件頁被允許，搜尋不被允許。這是可辯護的明確界線。 |

## 7. Phase 1 勘查結果 (prior art & source sweep)

### 7.1 假設對照表 —— 哪些原有信念被推翻

| 原本相信 | 查證後 | 影響 |
|---|---|---|
| 需要無頭瀏覽器模擬實機輸入 | **錯。** 三個平台有兩個有官方 API，第三個的單件頁被 robots.txt 明確允許 | 主路徑從瀏覽器改為 API；瀏覽器降為備援 |
| Espacenet 沒有摘要、文字不好複製 | **是網頁 UI 的限制，不是資料的限制。** EPO OPS API 有 abstract / claims / description / fulltext | 使用者最大的兩個痛點由同一個 API 一次解決 |
| Google Patents 難拿圖與原文件 | **部分錯。** 實測 `US20250383260A1`，圖檔 URL 可直接定址（15 張，`patentimages.storage.googleapis.com/...`）| Google Patents 升格為便宜的圖片來源之一 |
| 非英語案要自己處理翻譯 | **錯。** Google Patents 對中／日／韓案本來就提供英文機翻全文 | 本體確實不需翻譯引擎；extension 的定位是「翻成繁中」 |
| PATENTSCOPE 可以接 | **實際上不可行。** 官方為 SOAP Web Service、CHF 2,000/年、每 IP 每分鐘 <10 次擷取 | 降為「在原站開啟」深連結 |

### 7.2 實測記錄（2026-08-20）

抓取 `https://patents.google.com/patent/US20250383260A1/en`，實得：

| 欄位 | 結果 |
|---|---|
| 標題、摘要、說明書全文、CPC 分類、法律狀態 | ✅ 皆為純文字 |
| 圖式 | ✅ 15 張，URL 可直接定址 |
| 請求項 (claims)、Download PDF、引證、同族 | ⚠️ **本次未取得** —— 可能存在於原始 HTML 但被轉檔丟失，**未經證實，實作時須重驗** |

### 7.3 資料源分工結論

| 來源 | 角色 | 憑證 |
|---|---|---|
| **EPO OPS** | **骨幹**：號碼正規化、同族、法律狀態、圖式、原文件 PDF（逐頁）、claims/description | 需免費開發者帳號 + OAuth2 金鑰 |
| **Google Patents 單件頁** | **非英語案（CN/JP/KR/TW）的文字主源**（英文機翻）＋ 摘要品質 ＋ 圖片備援 | 無 |
| **USPTO ODP** | **美國案**的原文件與審查歷程 | 需免費 API Key |
| **TIPO 開放資料 API** | 台灣案（使用者常看） | 待確認 |
| PATENTSCOPE | 僅深連結 | — |
| BigQuery `patents-public-data` | 保留給未來的技術地圖擴充 | Google Cloud 帳號 |

### 7.4 開源盤點 (OSS inventory)

| 候選 | 用途 | 授權／維護 | 決定 |
|---|---|---|---|
| `python-epo-ops-client` | EPO OPS 客戶端，**內建節流與配額例外處理** | 活躍 | **採用** —— 省掉 BR-6 最麻煩的一塊 |
| `patent_client` | 統一 ORM 客戶端（USPTO/EPO/EUIPO/INPADOC），async + Pydantic v2 | 活躍（5.0.x） | **採用**（評估後決定覆蓋範圍） |
| `PatZilla` | 完整專利檢索平台，已整合 OPS/DEPATISnet/USPTO | **AGPL / EUPL**；2020–2022 停擺後仍在做 Python 3 遷移 | **不採用**。理由：(a) AGPL 對後續分享有牽制；(b) 半遷移中的維護狀態；(c) 定位是檢索平台，本案是單件深度閱讀，重心不同。**2026-08-20 已查閱其公開文件，架構揭露不足，參考價值低於預期。** |

> 此決定已記錄，後續 session **不需重新評估 PatZilla**。

### 7.5 差異化陳述（誠實版）

本工具**不會**在檢索與分析能力上勝過 PatSnap / Orbit，也不該嘗試。它唯一的勝場是：

> **現有免費工具沒有任何一個把「可複製的全文 ＋ 高品質圖式 ＋ 原文件 PDF ＋ 同族與分類」放在同一屏。** 使用者現在得開三個分頁手動拼。

這個定位站得住，但也**同時定義了邊界**：這是**閱讀器**，不是檢索引擎。

### 7.6 環境限制（已確認）

- Windows 11 本機、單人使用、非商業。
- 專案目錄 `D:\AIWork\PatentsGrabber` 目前為空，尚未初始化為 git repo。
- 無雲端部署需求；啟動方式應為單一指令／單一捷徑。

## 8. 尚未確定的事 —— Spike 計畫（進入 PIM 前的硬性前置）

| # | 待驗證 | 驗證方式 | 若結果為否，如何翻盤 |
|---|---|---|---|
| S-1 | **EPO OPS 對 US / TW / CN / JP / KR 案的 description / claims 全文覆蓋率** | 取 10 件跨國別實際號碼逐欄位實查，做成覆蓋矩陣 | 該國別的文字主源改用 Google Patents 單件頁；OPS 只供同族／法狀／圖式／PDF |
| S-2 | **Google Patents 單件頁是否確實含 claims 與 Download PDF 連結** | 直接解析原始 HTML（非轉檔） | 原文件全面改由 OPS `fullimage` 逐頁取得後合併 |
| S-3 | **OPS 圖式對非英語案的可得性與畫質** | 同 S-1 的 10 件一併記錄 | 改用 Google Patents 的 `patentimages` 圖檔 |
| S-4 | **TIPO 開放資料 API 的實際欄位與申請門檻** | 讀官方 API 文件 | 台灣案降級為深連結，不整合 |
| S-5 | 4 GB/週配額在實際使用強度下是否夠用 | 記錄 spike 期間的實際流量 | 圖式改為延遲載入／降解析度 |

**S-1 是最高風險項**，因為使用者的管轄範圍橫跨 US/EP/TW/CN/JP/KR，而非英語案的全文覆蓋差異極大。

## 9. 前提與可翻盤條件 (premises & refutability)

**前提**

| 類型 | 內容 | 來源 | 狀態 |
|---|---|---|---|
| P-env | Windows 11、本機單人、專案目錄為空、非 git repo | 模型（已驗證） | 已驗證 |
| P-intent | 用途為研究方向確認與學習，非商業、非 FTO | **使用者** | 已由使用者裁定 |
| P-intent | 管轄範圍 US 為主，EP/WO、TW、CN/JP/KR 皆常看 | **使用者** | 已由使用者裁定 |
| P-intent | 翻譯不列入本體，做為 extension | **使用者** | 已由使用者裁定 |
| P-validity | 各資料源的 API 現況、配額、授權 | 模型（2026-08-20 網路查證） | 已驗證，**屬易變事實** |
| P-validity | OPS 對非英語案的全文覆蓋率足以支撐「讀懂技術」 | 模型 | **假設，未驗證 → S-1** |

**成立條件 (holds when)**：三個免費資料源的可用性與配額維持在 2026-08-20 查得的水準。

**會被推翻的情況 (overturned by)**：
- S-1 顯示非英語案的全文覆蓋不足 → §7.3 的來源分工需重寫（不影響 §1–§5）。
- EPO 或 USPTO 變更免費層條件 → 需重新評估 BR-6 與整體可行性。
- 使用者的用途從「讀懂技術」轉向「檢索／landscape」→ §4 的邊界 1 失效，本文件需整份重做。

**證據層級**：資料源能力為官方文件與第三方客戶端文件（二手）＋ 一件實測（一手）；覆蓋率為推論，尚無證據。

**review-when**：任一資料源公告變更免費層條件時；或 S-1 完成時（屆時本文件 §7.3 與 §9 需更新）。
